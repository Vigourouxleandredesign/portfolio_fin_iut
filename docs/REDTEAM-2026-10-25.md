# Red team — préproduction Netlify (25/10/2026)

**Cible :** https://vigourouxleandre.netlify.app (build `main` au commit `a04fde4`, après les correctifs listés en §2).
**Méthode :** attaque et mesure **du site publié**, sans lire le code comme source de vérité : requêtes HTTP brutes (≈ 110 requêtes, dont une soixantaine de variantes de chemins), navigateur réel (Playwright : desktop 1440 px, mobile 390 px, 320 px, sans JavaScript, clavier), Lighthouse (mobile simulé 4G lent + CPU ×4, et desktop), axe-core, extraction du texte rendu, contrôle des liens externes.
**Limites :** pages `/jury` vues **sans** mot de passe uniquement (le contenu protégé n'a pas été ouvert) ; pas de test sur appareil physique ; Lighthouse varie de ± 10 points d'une exécution à l'autre (l'accueil mobile a donné 46, 49 et 61).

---

## 1. Verdict

Le site est **solide sur la sécurité de base, l'accessibilité et le SEO technique**, et **fragile sur la performance mobile** de l'accueil et de MagicalLab (les deux pages 3D).
La red team a trouvé **un défaut grave de ma propre protection du jury** (§2, R1), corrigé et vérifié en production dans l'heure. Rien d'autre n'est bloquant pour la mise en ligne du 28/10 ; deux points (§3, P1) méritent d'être traités avant d'envoyer le lien aux recruteurs.

## 2. Corrigé pendant la red team (déjà en production)

| # | Gravité | Constat | Correctif | Vérifié |
|---|---|---|---|---|
| R1 | 🔴 **Critique** | **Le verrou jury se contournait.** `//jury`, `///jury`, `//pages/jury/index.html` servaient les pages jury ; `/JURY/fiches/visualcom/mission-reflection.pdf` et `/Jury/fiches/village-jeunes/project-sheet.pdf` servaient les **PDF**, sans mot de passe. Cause : ma fonction de protection (L7s) ne couvrait que des chemins écrits à l'identique, alors que le CDN sert les fichiers sans tenir compte de la casse et fusionne les `/` répétés. | Fonction montée sur `/*`, qui **normalise** le chemin (minuscules, `/` fusionnés, `.`/`..`, encodages multiples, caractères de contrôle) et protège tout segment nommé `jury`. Échec fermé si le chemin est illisible. | 18 chemins × (sans identifiants / faux identifiants) + 3 pages publiques = **39 tests E2E prod verts** ; 18 variantes supplémentaires testées (`;`, `%2e`, `%5C`, `..`, HTTP/1.0…) : 401 ou 404, jamais 200 ; tests unitaires dédiés (31 chemins). |
| R2 | 🟠 Majeur | **Domaine factice partout** (`REMPLACER-PAR-LE-DOMAINE`) dans canonical, og:image, sitemap, robots : aperçus de partage cassés (LinkedIn, Slack, messageries), moteurs de recherche pointés vers un domaine inexistant. | Domaine réel posé ; og:image **absolues** ; images de partage dédiées pour 5 projets (`public/og/`) ; `twitter:card` ajouté ; test qui interdit le retour du placeholder. | HTML en ligne relu ; `og/lab-horizon.jpg` en 200. |
| R3 | 🟠 Majeur | **Poids** : `bust.glb` 7,9 Mo (6 textures PNG/JPEG de 6,9 Mo sur un modèle sans coordonnées UV) ; `splash-ember.png`, logo Visualcom et capture : 1,6 Mo inutiles. | `bust.glb` 1,2 Mo (textures 1024 px en WebP + Draco rétabli, rendu identique comparé image à image) ; −1,6 Mo d'images ; test de budget. | Capture avant/après identique. |
| R4 | 🟡 Mineur | **Impression « site pas fini »** à l'ouverture : texte, puis image du buste, puis 3D qui « saute ». | **Voile d'ouverture** dans la DA (faisceau, monogramme tracé à l'or, « Le sanctuaire s'éveille »), levé quand polices + images du héros + 3D sont prêtes (0,9 s min, 3,2 s max), une fois par session, jamais avec « réduire les animations », secours 100 % CSS à 5 s. | Captures image par image ; 5 tests unitaires. |

Avant L7s, tout l'espace était ouvert (incident déjà documenté). Le mot de passe n'a jamais fuité ; **je recommande tout de même de le changer** avant d'envoyer le lien au jury (30 s dans Netlify).

## 4. Ce qui est bien (à ne pas casser)

- **En-têtes de sécurité complets** : CSP sans `unsafe-inline` ni `unsafe-eval` (seul `wasm-unsafe-eval` pour Draco/Rapier), HSTS preload, COOP `same-origin`, `X-Frame-Options: DENY`, `nosniff`, `Permissions-Policy` fermée. Aucun cookie.
- **Surface exposée minimale** : `.git`, `.env`, `package.json`, `netlify.toml`, `_headers`, sources `src/`, tests, docs, scripts, edge function, source maps → tous en **404** ; pas de listing de dossiers.
- **Jury à échec fermé** : variable absente → 503 (jamais de contenu en clair) ; comparaison en temps constant ; pages et PDF en `no-store` + `noindex` ; dépôt GitHub **privé** ; secrets absents du code (garde `check:secrets`).
- **Accessibilité** : Lighthouse 100 sur les 4 pages mesurées, axe sans violation, 1 seul `h1` par page, aucun saut de titre, aucun ID dupliqué, aucune image sans `alt`, aucun lien sans nom, ordre de tabulation logique, lien d'évitement en premier, `prefers-reduced-motion` respecté (voile, poussière, 3D).
- **Rendu** : aucun défilement horizontal à 320 px, **CLS = 0** (0,025 sur le CV), polices préchargées, images WebP, `<html lang="fr">`, 404 personnalisée.
- **SEO** : description et Open Graph sur toutes les pages, canonical cohérent, sitemap = 13 pages, robots cohérent, jury exclu et `noindex`.
- **Liens externes** : 8 liens, tous en 200, tous `rel="noopener noreferrer"`.
- **Processus** : CI complète sur chaque commit (audit des dépendances, types, secrets, 305 tests, build, E2E), Dependabot, tests de non-régression pour chaque défaut trouvé (jury, domaine, poids du buste, voile).
- **Pages légères** : CV 99/100 (134 Ko), Lab Horizon 93 (589 Ko).
